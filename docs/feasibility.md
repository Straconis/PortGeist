# Feasibility and open questions

1. Can a small fully local vision-language model accurately read dense BIOS, recovery, and desktop interfaces?
2. What are the latency, memory, thermal, and power limits on a Pi 5 alone?
3. Which models actually run on AI HAT+ 2, and can they produce dependable UI actions?
4. Is OCR plus a small planning model more reliable than a single vision-language model?
5. Which USB HID bridge works reliably before the target OS boots?
6. What HDMI capture devices preserve readable text and acceptable latency?
7. How should multiple displays, unusual resolutions, blank screens, and HDCP be handled?
8. How should the agent select and switch LAN/onboard models without losing state?
9. What objective and risk policy format makes approval requests understandable?
10. How can we safely test autonomy in a virtualized or sacrificial environment?
11. Is virtual USB boot media practical in the selected hardware architecture?
12. What is the right size, power budget, and enclosure design for portability?
13. Are PortGeist name, GitHub namespace, and trademarks sufficiently clear for release?

No answers should be treated as validated until tested and documented.
